# Offline Token Verification Guide

## Overview

Tokens generated by Jitter Distill can be **signed with a private key** (server-side) and **verified offline** (client-side) using only the public key. No server access required!

## Use Cases

✓ License key validation (offline)  
✓ API token verification (no DB lookup)  
✓ Distributed system authentication  
✓ Air-gapped environments  
✓ Client-side validation

## Quick Start

### 1. Generate Key Pair (One-Time Setup)

```bash
# On server (keep private.pem SECRET!)
jitter-token --gen-keys --key-bits 2048

# Output:
#   private.pem (keep on server, chmod 600)
#   public.pem  (distribute to clients)
```

### 2. Server: Sign Tokens

```go
package main

import (
	"os"
	jd "github.com/nimish-nirmal/jitter-distill"
)

func main() {
	// Load private key (server-side only)
	privateKey, _ := os.ReadFile("private.pem")

	// Generate entropy pool
	pool := jd.NewEntropyPool(jd.DefaultConfig())
	defer pool.Close()

	// Generate and sign token
	token, _ := pool.GenerateToken()
	signed, _ := jd.SignToken(token, privateKey)

	// Send to client:
	// JSON: {"token": signed.Token, "signature": "hex_encoded_signature"}
	_ = signed
}
```

### 3. Client: Verify Offline (NO SERVER NEEDED!)

```go
package main

import (
	"os"
	jd "github.com/nimish-nirmal/jitter-distill"
)

func main() {
	// Load public key (safe to share!)
	publicKey, _ := os.ReadFile("public.pem")

	// Receive from server: token + signature
	receivedToken := "abc123..."
	receivedSignature := []byte{...}

	// Verify OFFLINE - no HTTP request!
	signed := &jd.SignedToken{
		Token:     receivedToken,
		Signature: receivedSignature,
	}

	valid := jd.VerifySignedToken(signed, publicKey)
	if valid {
		fmt.Println("Token is valid!")
	} else {
		fmt.Println("Token is INVALID!")
	}
}
```

## CLI Usage

### Generate Keys

```bash
jitter-token --gen-keys
# Creates: private.pem, public.pem

# Custom key size
jitter-token --gen-keys --key-bits 4096
```

### Sign Token

```bash
jitter-token --sign private.pem --count 1

# Output:
# Token: abc123...
# Signature: deadbeef...
#
# To verify (offline, no server):
#   jitter-token --verify public.pem --token abc123...
```

### Verify Token

```bash
# Interactive mode
jitter-token --verify public.pem --token abc123...
# Enter signature (hex): deadbeef...

# ✓ Token is VALID (verified offline, no server needed)
```

## Security Considerations

### Private Key (Server)
- Store securely with restricted permissions (chmod 600)
- Never distribute or commit to git
- Use HSM/KMS for production
- Rotate periodically

### Public Key (Client)
- Safe to distribute freely
- Can be embedded in applications
- Can be hardcoded in clients

### Token Structure
```
{
  "token": "256-bit hex string",
  "signature": "256-byte RSA signature (hex encoded)"
}
```

## Example Workflows

### Workflow 1: License Validation

```
1. Vendor generates private/public key pair
2. Vendor embeds public key in software
3. Server generates tokens (license keys) with private key
4. Client software verifies tokens offline (no phone-home)
5. Tokens are tamper-proof (can't forge without private key)
```

### Workflow 2: API Authentication

```
1. Auth server signs JWT-like tokens with private key
2. API gateway verifies tokens offline with public key
3. No database lookup required
4. Tokens expire naturally (optional timestamp in token)
```

### Workflow 3: IoT Device Authentication

```
1. Manufacturer signs device tokens during provisioning
2. Devices carry public key in firmware
3. Server validates device tokens offline
4. No central server needed for verification
```

## Implementation Details

- **Algorithm**: RSA-PKCS1v15 with SHA-256
- **Key Sizes**: 2048-bit (default), 4096-bit (high security)
- **Signature Size**: 256 bytes (2048-bit key) or 512 bytes (4096-bit key)
- **Encoding**: PEM format for keys, hex for signatures

## Troubleshooting

**Q: Signature verification fails?**  
A: Ensure you're using the matching public key for the private key that signed the token.

**Q: Can I use ECDSA instead of RSA?**  
A: Currently RSA only. ECDSA support can be added if needed.

**Q: How big are signatures?**  
A: 256 bytes for 2048-bit RSA key.

**Q: Is it safe to embed public key in client?**  
A: Yes! Public keys are designed to be public. Only private keys must be kept secret.
